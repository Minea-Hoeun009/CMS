## ១. ទិដ្ឋភាពទូទៅនៃប្រព័ន្ធសុវត្ថិភាព

ប្រព័ន្ធគ្រប់គ្រងសាលារៀន (CMS) ជំនាន់ ៤.០ ត្រូវបានអភិវឌ្ឍឡើងដោយប្រើប្រាស់ស្តង់ដារសុវត្ថិភាពកម្រិតខ្ពស់ (Enterprise-grade Security) ដើម្បីធានាថាទិន្នន័យសិស្ស គ្រូ ពិន្ទុ និងវត្តមានត្រូវបានការពារយ៉ាងរឹងមាំ៖
- **Google / Gmail Sign-In:** ផ្ទៀងផ្ទាត់ Firebase ID Token ដោយផ្ទាល់លើ Server តាមរយៈ Google OAuth2 API ផ្លូវការ។ មិនអនុញ្ញាតឱ្យគណនី Google ណាមួយតម្លើងសិទ្ធិជា Admin ដោយស្វ័យប្រវត្តិនោះឡើយ។
- **Telegram Login:** ផ្ទៀងផ្ទាត់ហត្ថលេខាឌីជីថល HMAC-SHA256 និងភាពស្រស់នៃ Token (< 24 ម៉ោង)។
- **Admin-Controlled Approvals:** រាល់គណនីចុះឈ្មោះថ្មីត្រូវស្ថិតក្នុងស្ថានភាព `pending` (រង់ចាំការអនុម័ត) ជាដាច់ខាត។ មានតែ Super Admin ឬ Admin ប៉ុណ្ណោះដែលអាចអនុម័តបាន។
- **Session Security:** ប្រើប្រាស់ Session Token ដែលផ្ទុកក្នុង `sessionStorage` (លុបដោយស្វ័យប្រវត្តិកាលណាផ្ទាំង Browser បិទ) អមដោយការកំណត់ម៉ោងផុតកំណត់ (12 ម៉ោង) និង Idle Timeout (2 ម៉ោង)។
- **Rate Limiting:** បិទខ្ទប់ការប៉ុនប៉ងទាយពាក្យសម្ងាត់លើសពី ៥ ដងក្នុងរយៈពេល ១៥ នាទី។
- **Audit Logging:** កត់ត្រារាល់សកម្មភាពទាំងអស់ចូលទៅក្នុងតារាង `AuditLogs` ដោយស្វ័យប្រវត្តិ និងលុបបំបាត់ពាក្យសម្ងាត់ ឬ Token ចេញពីកំណត់ហេតុ (Redaction)។

## ២. ការកំណត់ Google Apps Script និង Script Properties

### ជំហានទី ១៖ បើកគម្រោង Apps Script
១. បើក Google Sheets ដែលជា Database របស់លោកអ្នក។  
២. ចុចលើ Menu **Extensions (ផ្នែកបន្ថែម)** > **Apps Script**។  
៣. ចម្លងកូដទាំងស្រុងពីឯកសារ `google-apps-script/Code.gs` មកបិទភ្ជាប់ (Paste) ជំនួសកូដចាស់។

### ជំហានទី ២៖ កំណត់ Script Properties (អាថ៌កំបាំងសុវត្ថិភាព)
១. នៅក្នុងផ្ទាំង Apps Script ចុចលើរូប **⚙️ Project Settings (ការកំណត់គម្រោង)** នៅខាងឆ្វេង។  
២. អូសចុះមកក្រោមត្រង់ចំណុច **Script Properties (លក្ខណសម្បត្តិស្គ្រីប)** រួចចុច **Add script property**៖

| Property Name | ឧទាហរណ៍តម្លៃ | ការពន្យល់ |
| :--- | :--- | :--- |
| `ADMIN_SETUP_TOKEN` | `SECURE_SETUP_TOKEN_2026_CMS` | Token សម្រាប់ការពារការ Reset ឬ Setup តារាង |
| `TELEGRAM_BOT_TOKEN` | `7482819283:AAH...` | Bot Token ដែលទទួលបានពី @BotFather |
| `FIREBASE_PROJECT_ID` | `cms-v01` | Project ID របស់ Firebase |

៣. ចុច **Save script properties**។

### ជំហានទី ៣៖ Deploy ជា Web App
១. ចុចប៊ូតុង **Deploy (ដាក់ឱ្យប្រើប្រាស់)** > **New deployment (ការដាក់ឱ្យប្រើប្រាស់ថ្មី)**។  
២. ជ្រើសរើសប្រភេទ **Web app**។  
៣. កំណត់រចនាសម្ព័ន្ធ៖
   - **Execute as:** `Me (អាសយដ្ឋាន Gmail របស់អ្នក)`
   - **Who has access:** `Anyone (អ្នកណាក៏ដោយ)`
៤. ចុច **Deploy** រួចចម្លង **Web App URL** (ឧ. `https://script.google.com/macros/s/.../exec`) យកទៅដាក់ក្នុង `js/config.js` ត្រង់អថេរ `SCRIPT_URL`។

## ៣. ការកំណត់ Firebase Authentication (Google Sign-In)

១. ចូលទៅកាន់ [Firebase Console](https://console.firebase.google.com/) រួចជ្រើសរើសគម្រោង `cms-v01`។  
២. ចូលទៅកាន់ម៉ឺនុយ **Build** > **Authentication**។  
៣. ចុចលើផ្ទាំង **Sign-in method** > **Add new provider** > ជ្រើសរើស **Google**។  
៤. ចុច **Enable** រួចជ្រើសរើស Support email របស់សាលា ហើយចុច **Save**។  
៥. ចូលទៅកាន់ផ្ទាំង **Settings** ក្នុង Authentication > **Authorized domains**៖
   - បន្ថែម Domain របស់លោកអ្នក (ឧ. `cms-v01.firebaseapp.com`, `cms-v01.web.app`, ឬ Custom Domain របស់សាលា)។  
   - ប្រសិនបើសាកល្បងលើកុំព្យូទ័រ សូមប្រាកដថាមាន `localhost`។

## ៤. ការបង្កើត និងកំណត់ Telegram Bot (@BotFather)

ដើម្បីឱ្យគ្រូបង្រៀនអាចចូលប្រព័ន្ធតាមរយៈ Telegram Login Widget ផ្លូវការ៖
១. បើកកម្មវិធី Telegram រួចស្វែងរកគណនី `@BotFather`។  
២. ផ្ញើពាក្យបញ្ជា `/newbot` រួចដាក់ឈ្មោះ Bot និង Username (ត្រូវបញ្ចប់ដោយ `_bot` ឧ. `krou_digital_bot`)។  
៣. `@BotFather` នឹងផ្តល់ជូន **HTTP API Token** (ឧ. `7482819283:AAH_abcdef123...`)។  
៤. ចម្លង Token នេះទៅដាក់ក្នុង Script Properties នៃ Google Apps Script ក្រោមឈ្មោះ `TELEGRAM_BOT_TOKEN`។  
៥. កំណត់ Domain សម្រាប់ Telegram Widget ដោយផ្ញើទៅ `@BotFather`៖
   - វាយបញ្ជា `/setdomain`  
   - ជ្រើសរើស Bot របស់លោកអ្នក  
   - បញ្ចូល Domain នៃគេហទំព័ររបស់លោកអ្នក (ឧ. `cms-v01.firebaseapp.com`)។

## ៥. ការចុះឈ្មោះគណនី និងដំណើរការអនុម័ត (Account Approval Workflow)

ដើម្បីធានាសុវត្ថិភាពទិន្នន័យសាលា គ្មានបុគ្គលណាម្នាក់អាចចូលមើលទិន្នន័យបានដោយគ្មានការអនុញ្ញាតឡើយ៖

```
[គ្រូ/បុគ្គលិកថ្មី] ──► ចុចចូលតាម Google / Telegram ──► បង្កើតសំណើស្ថានភាព "pending"
                                                              │
                                                              ▼
                                                   [ផ្ទាំងរង់ចាំការអនុម័ត]
                                                              │
                                                              ▼
[Super Admin ឬ Admin] ──► បើកផ្ទាំង "គ្រប់គ្រងគណនី" ──► ពិនិត្យមើល និងចុច "អនុម័ត"
                                                              │
                                                              ▼
[គណនីក្លាយជា approved] ──► គ្រូអាចចូលប្រើប្រាស់មុខងារបង្រៀនបានភ្លាមៗ
```

### របៀបដែល Admin អនុម័តគណនី៖
១. Super Admin ឬ School Admin ចូលក្នុងប្រព័ន្ធ។  
២. ចុចលើឈ្មោះរបស់ខ្លួននៅជ្រុងខាងក្រោមឆ្វេង (Sidebar) ដើម្បីបើកផ្ទាំងព័ត៌មានគណនី។  
៣. ចុចប៊ូតុង **«គ្រប់គ្រងគណនី» (Manage Accounts)**។  
៤. នៅក្នុងបញ្ជីគណនី លោកអ្នកនឹងឃើញអ្នកដែលមានផ្លាកសញ្ញាពណ៌លឿង **`Pending`**។  
៥. ជ្រើសរើសតួនាទីសមស្រប (ឧ. Homeroom Teacher, Subject Teacher) រួចចុចប៊ូតុងពណ៌បៃតង **«អនុម័ត» (Approve)**។

## ៦. ការគ្រប់គ្រងតួនាទី និងសិទ្ធិ (RBAC 5 Roles)

ប្រព័ន្ធបានកំណត់សិទ្ធិយ៉ាងតឹងរ៉ឹងចំនួន ៥ កម្រិត៖

| ល.រ | តួនាទី (Role) | សិទ្ធិអនុញ្ញាត | ដែនកំណត់ថ្នាក់រៀន (Class Scope) |
| :---: | :--- | :--- | :--- |
| **១** | **Super Admin** | គ្រប់គ្រងប្រព័ន្ធទាំងមូល, បង្កើត/គ្រប់គ្រង Admin, មើល Audit Logs, ដោះស្រាយអាសន្ន។ | គ្មានដែនកំណត់ (All) |
| **២** | **Admin (សាលា)** | គ្រប់គ្រងបញ្ជីវត្តមាន/ពិន្ទុទូទាំងសាលា, អនុម័តគ្រូ, បង្កើតថ្នាក់, មើលរបាយការណ៍សាលា។ មិនអាចតម្លើងជា Super Admin បានឡើយ។ | ទូទាំងសាលា (School-wide) |
| **៣** | **Homeroom Teacher (គ្រូប្រចាំថ្នាក់)** | គ្រប់គ្រងបញ្ជីសិស្ស, ស្រង់វត្តមានប្រចាំថ្ងៃ, ស្រង់ពិន្ទុ, បោះពុម្ពសៀវភៅតាមដាន និងតារាងកិត្តិយសក្នុងថ្នាក់របស់ខ្លួន។ | ត្រឹមថ្នាក់ និងបន្ទប់ដែលខ្លួនទទួលបន្ទុក |
| **៤** | **Subject Teacher (គ្រូបង្រៀនមុខវិជ្ជា)** | បញ្ចូលពិន្ទុមុខវិជ្ជាដែលខ្លួនបង្រៀន, ដាក់កិច្ចការផ្ទះ, កត់ត្រាវត្តមានម៉ោងរៀន។ | ថ្នាក់ និងមុខវិជ្ជាដែលបានចាត់តាំង |
| **៥** | **Student (សិស្សានុសិស្ស)** | មើលព័ត៌មានផ្ទាល់ខ្លួន, លទ្ធផលពិន្ទុ, វត្តមាន, កាលវិភាគ និងសេចក្តីជូនដំណឹង។ មិនអាចកែប្រែទិន្នន័យបានឡើយ។ | ត្រឹមលេខសម្គាល់សិស្សផ្ទាល់ខ្លួន |

## ៧. ការកំណត់សុវត្ថិភាព ២ ជាន់ (MFA) និងលេខកូដសង្គ្រោះបន្ទាន់

សម្រាប់គណនី Super Admin និង Admin ប្រព័ន្ធផ្តល់ជូននូវការការពារបន្ថែមជាមួយ TOTP Multi-Factor Authentication៖
១. ចុចលើផ្ទាំងគណនីផ្ទាល់ខ្លួន > ចុចប៊ូតុង **«MFA»**។  
២. ផ្ទាំងកំណត់ MFA នឹងបង្ហាញ QR Code និង Secret Key (Base32)។  
៣. ប្រើកម្មវិធី **Google Authenticator** ឬ **1Password** លើទូរស័ព្ទដៃដើម្បីស្កេន QR Code នេះ។  
៤. **សំខាន់បំផុត៖** ប្រព័ន្ធនឹងបង្កើតលេខកូដសង្គ្រោះបន្ទាន់ ៨ ខ្ទង់ចំនួន ៨ ឈុត (Backup Recovery Codes)។ សូមចុច **«ចម្លងលេខកូដទាំងអស់»** រួចរក្សាទុកក្នុងកន្លែងមានសុវត្ថិភាព សម្រាប់ប្រើប្រាស់ពេលបាត់ទូរស័ព្ទដៃ។

## ៨. ការត្រួតពិនិត្យកំណត់ហេតុសុវត្ថិភាព (Audit Logs)

សម្រាប់ Super Admin ដើម្បីធានាតម្លាភាព និងការទទួលខុសត្រូវ៖
១. ចុចលើផ្ទាំងគណនីផ្ទាល់ខ្លួន > ចុចប៊ូតុង **«សវនកម្ម» (Audit Logs)**។  
២. ប្រព័ន្ធនឹងទាញយកកំណត់ត្រាព្រឹត្តិការណ៍ទាំងអស់ពីតារាង `AuditLogs` ក្នុង Google Sheets៖
   - ពេលវេលា និងកាលបរិច្ឆេទជាក់លាក់
   - អ្នកដំណើរការ (User ID ឬ Email)
   - សកម្មភាព (ឧ. `GOOGLE_LOGIN_SUCCESS`, `APPROVE_USER`, `SAVE_SCORES`, `SET_STATUS_SUSPENDED`)
   - គោលដៅ និងលទ្ធផល (`SUCCESS`, `FAILED`, `BLOCKED`, `PENDING`)
   - ព័ត៌មានលម្អិត (ព័ត៌មានសម្ងាត់ដូចជា ពាក្យសម្ងាត់ និង Token ត្រូវបានលុបចេញដោយស្វ័យប្រវត្តិ)។
